1. Executive Overview

The THORRIJA Engineering Showcase presents five independent, deterministic computational models reconstructed from source code, displayed through a dark-industrial web application built with Vite + TypeScript. 2. Engineering Philosophy & Project Selection

Independent reconstruction: Every model is rebuilt from source code as an independent TypeScript implementation. The original projects are never executed inside demonstrations.

Real calculations: All outputs are computed from inputs. No hardcoded outputs, no fabricated results.

Determinism: Same input always produces the same output. Every random decision is unit_hash(seed, step, purpose, structural_digest(candidate)) — a pure function of (state, seed, step).

Intermediate stages: Demonstrations show processing stages, not just final results. Each section renders per-step observables, event logs, and intermediate data structures.

Fidelity classified: Each model carries a Level 1–4 rating with documented adaptations. Nothing is overclaimed.

Honest about limitations: Limitations are listed explicitly. Nothing is claimed that is not implemented and tested.

Project selection methodology: Projects were evaluated on technical depth, algorithmic complexity, implementation quality, originality, completeness, reproducibility, and educational value. Four projects were selected for interactive demonstrations; all ~24 discovered projects are documented in the catalog (Appendix D).

3. Wi-Fi Time Machine — Technical Chapter

Problem: Reconstruct wireless environment scanning history from raw iw/nmcli output, producing per-channel activity, timeline heatmaps, and sanitized exports.

Architecture

  • Input parser: iw scan-dump blocks and escaped nmcli tab-separated output
  • Deduplication: strongest signal per BSSID
  • Channel mapping: 802.11 freq→channel (2.4/5/6 GHz)
  • Security inference: AKM suite text → WPA/WPA2/WPA3 label
  • Timeline heatmap: rows = networks, columns = time buckets, glyph = signal tier
  • Export: SHA-256-truncated BSSID sanitization, JSON/CSV

Data Structures

ScanResult: { BSSID, SSID, channel, frequency, signal_dBm, security }
Tables: networks, observations, sessions

Algorithms

  • Parse BSS blocks from iw scan dump
  • nmcli escaped tokenizer (handling \: and \\)
  • Frequency-to-channel mapping for 2.4/5/6 GHz
  • Security inference from AKM suites
  • Networks × time-bucket heatmap

Processing Pipeline

Scan → parse → deduplicate (strongest signal) → register → aggregate by network/channel → render heatmap, sparkline, bars → sanitize → export.

Determinism

Same fixture → same output. Configurable epoch clock for reproducibility.

4. BLE Radar — Technical Chapter

Problem: Visualize Bluetooth LE device presence as a deterministic radar: device lifecycle (appeared→active→fading→disappeared), RSSI strength bands, hash→angle mapping, session replay.

Architecture

  • Scanners: bleak / demo / replay
  • RadarEngine: state machine + EMA
  • Snapshot → radar frame geometry (cell grid)
  • Curses UI → HTML canvas

Data Structures

Observation: { address, name, rssi, timestamp }
DeviceState: { RSSI EMA, state, trails }
DeviceSnap: { angle, band, state, jitter, visible }

Algorithms

  • State machine: appeared → active → fading → disappeared (15s/30s windows)
  • EMA RSSI smoothing (alpha=0.4): rssi = 0.6 × prev + 0.4 × new
  • RSSI strength bands: strong>=-40, near>=-55, mid>=-70, far>=-85, weak
  • Stable angle: SHA-256(address) → 0–360° (visual convention, not bearing)
  • Aspect-corrected polar geometry for radar frame
  • Replay cursor with seek/speed controls

Processing Pipeline

Ingest observations → RadarEngine (state machine + EMA) → snapshot → radar frame → curses UI / HTML canvas → session replay.

Limitations

  • No BLE hardware (BlueZ/bleak); no live scanning
  • RSSI is signal strength, never physical distance
  • Angle is a visual convention from MAC hash

5. Process Ecosystem Monitor — Technical Chapter

Problem: Reconstruct Linux process ecosystem from synthetic /proc snapshots: process lifecycle, CPU jiffie accounting, process tree, orphan re-homing, PID-reuse detection.

Architecture

  • Parser: /proc/[pid]/stat (nested-paren comm handling), /proc/[pid]/statm, /proc/stat, /proc/meminfo, /proc/loadavg
  • EcosystemState: lifecycle, CPU, memory, tree
  • Renderer/UI: process table, tree visualization, metrics

Data Structures

ProcessSnapshot: { pid, ppid, comm, state, utime, stime, starttime, RSS }
ProcessState: { lifecycle, CPU%, history rings }
SystemSample: { system CPU, RAM, load }

Algorithms

  • CPU% from jiffie delta normalized per-core
  • Identity: (pid, starttime) with PID reuse detection
  • Tree from ppid with orphan re-homing via graveyard (max 512)
  • Lifecycle: new → active/idle → dying → dead

Processing Pipeline

  • Collect /proc snapshots → parse → build process state → compute CPU% → build tree → detect PID reuse → render table/tree/metrics

Limitations

  • No live /proc access; synthetic snapshots only
  • No curses terminal UI
  • No real-time process monitoring

6. Terminal Generative Engine — Technical Chapter

Problem: Deterministic generative art: flowfield, plasma, and attractor modes, all computed from a stateless splitmix64 RNG with O(1) frame seeking.

Architecture

  • Stateless splitmix64 RNG: every value = f(seed, frame, salt, index); no PRNG state kept
  • Palettes: continuous 1-D color stops with linear interpolation
  • xterm-256 color mapping
  • Framebuffer: W×H pixel canvas, half-block terminal cell encoding
  • Render modes: flowfield, plasma, attractor
  • World fingerprint: SHA-256 over mode+frame+params+pixels

Algorithms

  • Flowfield: analytic angle field (sum of seed-derived sine harmonics over normalized coordinates); particles trace K-segment streamlines
  • Plasma: closed-form per-pixel color fields (4 formulas)
  • Attractor: Clifford/Dejong strange map with coefficient probing; density accumulation with log+gamma tone curve

Processing Pipeline

Seed → parameters → pixels → render → fingerprint → export.

Limitations

  • No terminal/ANSI output
  • No file export (GIF/PNG/ANS); pixel arrays exported as data only
  • Original project has 5 failing tests — not reproduced here

7. The Box — Scientific Chapter

The Box is a relational/computational model for the study of emergent relational structure. Six rewriting rules (GATHER, BOND, TAG_PROP, QUIET, DESCEND, FUSE) operate on an arc-incidence multi-digraph substrate. Nothing in the kernel stores identity, lineage, community, generation, or clustering — those are derived from arc tags alone by observers.

Kernel — Arc-Incidence Multi-Digraph

  • Node: {id, tag, payload (Float64Array), born}
  • Arc (relation): {id, src, dst, tag, w, clock}
  • Shared id space: nodes and arcs share one counter; any id resolves to a node or arc
  • Second-order structure: arcs may have arcs as endpoints
  • Invariants I1–I4: unique ids, no dangling arcs, caps, payload dimension

Six Foundry Rules (data, not code)

RuleMatchSelectEffectTagWeight
GATHERin_nodes ≥ 2a=in_nodes, b=in_nodes (distinct)add_arc(a→b)1 (PULL)0.6
BONDco_in_nodes k=2 ≥ 1y=co_in_nodes(tag=2)add_arc(anchor→y)2 (BOND)0.4
TAG_PROPout_nodes ≥ 1teacher=out_nodesset_node_tag(anchor, teacher.tag)—1.0
QUIETsince_inflow ≥ 30—set_node_tag(anchor, 5)5 (QUIET)1.0
DESCENDnode_tag=5, free_nodes≥1, free_arcs≥2child=newadd_node(child), add_arc(anchor→child)3 (DESCEND)0.9
FUSEout_arcs tag=3 ≥ 2, payload_close ≤ 0.05survivor=clones, twin=clones (distinct)add_arc(twin→survivor), del_node(twin)4 (EQUIV)1.0

Engine — Four Policies

  • canonical: seed-free, picks structurally-smallest site. Starves lineage formation; reference policy for reproducibility.
  • uniform: argmax unit_hash over all sites; relabelling-equivariant
  • weighted: argmax weight × unit_hash over sites
  • roundrobin: cycle through present rules; structurally-first site of each

Possibility Space

  • Finite, exactly enumerable, seed-independent set of (rule, anchor) pairs
  • Site = rule enabled at anchor where all predicates hold AND roles resolve
  • canonical_key: seed-independent digest of the space
  • Sampling via unit_hash argmax (relabelling-equivariant)

Identity & Lineage (derived structure)

  • descent_map: TAG_DESCEND arcs → {parent: [children]}
  • parents: {child: parent} with ambiguous-child tracking
  • lineage_depths: DFS with cycle detection; cycles reported, not silently broken
  • identity_classes: union-find over TAG_EQUIV arcs, including retired endpoints
  • fused_fraction: fused nodes / (live + retired) — scale-free, does not saturate with node cap

Structural Metrics

  • degree_tables: in/out-degree over node-node arcs; Gini coefficient
  • components: union-find connected components
  • beta0_beta1: Euler-exact on incidence graph; beta1 = ‖arcs‖ − ‖objects‖ + beta0
  • component_size_profile: n, max, mean, entropy, largest_frac
  • modularity: deterministic Louvain (single-level, deterministic tie-breaking)
  • shannon_entropy: over count distributions

Named Observables (14)

  • n_nodes, n_arcs, arc_density, beta0, beta1
  • mean_in_degree, mean_out_degree, max_in_degree, gini_in_degree
  • largest_component_frac, tag_entropy
  • mean_lineage_depth, max_lineage_depth
  • n_identity_classes, n_fusion_classes, fused_nodes, fused_fraction

Null Models

  • degree-preserving rewire: double-edge swaps; preserves every in-/out-degree; destroys higher-order structure (Milo et al. 2002)
  • tag permutation: preserves tag multiset; destroys which node carries which label
  • homogeneous: labels erased, weights normalised; keeps topology

p-Values

Empirical one-sided p-value with +1 correction:

p = (count(null ≥ real) + 1) / (null_count + 1)

Reachability floor: 1/(null_count + 1). If floor > alpha (0.01), test is not attainable.

Provenance

Experiment fingerprint is BLAKE2b-16 over: name, seed sum, steps, substrate_seed, ruleset_id, ruleset_hash, config, fingerprint_version. Two records with same fingerprint are the same experiment.

Limitations

  • BLAKE2b not byte-compatible with Python hashlib.blake2b. Graph hashes, unit_hash, structural_digest, experiment fingerprints differ.
  • No Koopman analysis (requires numpy linear algebra)
  • No classifier gates (G1–G4); depends on Koopman outputs not implemented
  • No window invariance battery
  • No SQLite/persistence layer; JSON export/import only
  • No CLI or store API

9. Algorithms & Implementation Details

Wi-Fi Time Machine

  • BSS block parsing: tokenize iw scan dump blocks; extract BSSID, freq, signal, SSID, channel, security (AKM)
  • nmcli tokenizer: escaped tab-separated fields
  • Deduplication: keep strongest signal per BSSID
  • Channel mapping: 2.4 GHz (2412–2484, 2484→14), 5 GHz (5000–5900), 6 GHz (5925–7125)
  • Security inference: AKM suite 00-0f-ac:2 → WPA2, :8 → WPA3

BLE Radar

  • EMA: rssi_t = 0.6 × rssi_{t-1} + 0.4 × rssi_raw
  • Strength bands: strong≥−40, near≥−55, mid≥−70, far≥−85, weak
  • Angle: SHA-256(address)[0:2] / 65536 × 360°
  • Lifecycle: ACTIVE_WINDOW=15s, GONE_WINDOW=30s

Process Ecosystem Monitor

  • CPU%: Δ(utime+stime) / (interval × CLK_TCK × ncores) × 100
  • System CPU: busy_delta / total_delta × 100
  • Identity: (pid, starttime); starttime change → PID reuse
  • Orphan re-homing: reparent to init (pid 1)
  • Graveyard: max 512 retained entries

Terminal Generative Engine

  • RNG: splitmix64-style; every value = f(seed, frame, salt, index)
  • Flowfield: analytic angle field (sine harmonics); particle streamlines
  • Plasma: closed-form per-pixel color fields
  • Attractor: Clifford/Dejong strange map
  • Fingerprint: SHA-256(mode + frame + params + pixels)
  • O(1) seek: any frame renderable without computing predecessors

The Box

  • unit_hash: BLAKE2b(seed‖step‖purpose‖structural_digest) / 2^64
  • graph_hash: BLAKE2b-32 over sorted nodes + arcs + retired
  • structural_digest: BLAKE2b-16 over hops-ball, sorted by sub-digest
  • Role resolution: argmax unit_hash over candidates (structural digest)
  • Batch effects: add_node first, then remaining effects with pre-resolved refs
  • del_node with preserve_arc_tags: witness arcs survive node deletion

13. Reproducibility & Demonstration Instructions

Within-TypeScript Reproducibility

Same (input, seed, ruleset) → identical trajectory. Every random decision is unit_hash(seed, step, purpose, structural_digest(candidate)) — a pure function of (state, seed, step). No hidden stream state. Steps can be replayed in isolation.

Relabelling Equivariance

traj(P(s0), seed) == P(traj(s0, seed)) for any permutation P. Renumbering the substrate permutes candidates but leaves each candidate's structural digest unchanged; argmax selection commutes with relabelling.

Cross-Language Reproducibility

Not byte-compatible. Python and TypeScript produce different BLAKE2b outputs for the same input:

  • Graph hashes differ
  • Experiment fingerprints differ
  • Trajectories with same seed diverge (different rules fire at each step)

For cross-language validation, compare equivalent structural properties, not hash values.

Appendix A — Glossary

  • RSSI: Received Signal Strength Indicator — signal strength in dBm; a strength measure, not distance
  • EMA: Exponential Moving Average — exponential smoothing for noisy signals
  • Jiffies: Linux kernel time units (CLK_TCK = 100 by default on x86)
  • PID reuse: reuse of process identifiers when a PID is freed and reassigned
  • AKM: Authentication Key Management — authentication suites in Wi-Fi security
  • Half-block encoding: terminal encoding where each cell represents 2 vertical pixels
  • Splitmix64: 64-bit mixing function for deterministic stateless RNG
  • Arc-incidence multi-digraph: graph where nodes and arcs share one id space; arcs can point to arcs
  • Possibility space: finite, exactly enumerable set of enabled (rule, anchor) pairs
  • Relabelling equivariance: behaviour invariant under renumbering of object ids
